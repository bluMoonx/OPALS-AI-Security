# Prompt-Injection Dataset — Sathwik (OPALS Group 21)

600 live OpenClaw sessions (`kimi-k2.5:cloud`, OpenClaw 2026.7.1) for the
prompt-injection track: **technique-level** injection attacks (benign-canary
probes) plus benign controls. Same `Session` schema as `chenhao-data_release/`,
so it merges directly into the general model.

---

## ⚠️ WHICH FILE TO USE — read this before pooling anything

| use case | file | why |
|---|---|---|
| **detector work / anything measuring over-block** | **`sessions_v2controls.jsonl`** | length-matched controls (trap 1) |
| **the 400 attacks only** (e.g. general model) | either — attack rows are byte-identical | but see trap 2 about labels |
| reproducing results published before 2026-07-27 | `sessions.jsonl` | kept unchanged on purpose |

### Trap 1 — `sessions.jsonl` still contains the length-confounded controls

Its 200 controls are **3–18 words** while the attacks are **10–74**. The benign
*maximum* sits below the attack *median*, so "prompt longer than 18 words" separates
the two classes at **AUC 0.992 with zero false positives** — without looking at a
single security signal. Any model given a length feature finds that first.

`sessions_v2controls.jsonl` replaces those 200 with a length-matched re-collection
(median 29, range 6–71, 131 unique prompts vs 55). Length AUC drops **0.974 → 0.568**;
the best single threshold goes from catching **78.8%** of attacks to **1.0%**.

**Do not use `sessions.jsonl`'s controls for any over-block or false-positive number.**
That file is kept only so earlier published results stay reproducible.

### Trap 2 — these labels are canary string-match, not behavioural

`attack_succeeded` is set by matching the scenario canary in the reply. The general
model's own adjudication measured that the canary **misses 78.7% of true compliances**
(`general-model/combined_gold_summary.json`, `canary_recall_vs_behaviour = 0.213`).

Pooling `attack_succeeded` as-is would therefore enter roughly **4 of every 5**
genuinely compliant sessions as "safe". `human_label` does not help either — it is
598 safe / 2 suspicious, because benign canaries are not harmful under the team rubric.

**If pooling into the general model: run `behavioral_labeler.py` over these sessions
first**, so they carry the same label definition as the `newcats` rows.

### Trap 3 — `compliance_tiers.csv` has a `285` that is *not* the control count

`tier_label` reads `safe: 285 / suspicious: 185 / unsafe: 130`. That 285 is
**200 controls + 85 attacks the agent resisted**, not 285 controls. It looks identical
to the old group-doc Issue #1 miscount but is correct for what it measures. The
condition split lives in the `condition` column: **400 attack / 200 baseline**.

Compliance tier answers *"did the agent comply?"*; attack-vs-control is answered by
`condition`. Do not group on one when you mean the other.

## Composition (600 sessions, 0 failures)

- **400 attacks** = 8 technique subtypes × 50 (echo + escalate payload modes;
  `prompt_leaking` is echo/text-only).
- **200 controls** = 4 families × 50 benign prompts (including hard negatives).
- Attack success rate **315/400 = 78.8%**.

## Labels: the 3-tier compliance ladder

Attacks here use **benign canaries** (a successful attack only makes the agent emit a
harmless marker or make one low-stakes tool call — never a harmful action), so the
team's harm-based rubric labels almost all of them "safe". The meaningful signal is the
injection-compliance tier (in `compliance_tiers.csv`): `ignored` (resisted) ·
`text_echo` (said the canary) · `escalated` (took the injected tool action).

## `attack_category` (fixed 2026-07-27, group-doc Issue #1)

All attack rows carry `attack_category = "direct_prompt_injection"` — a category
`scigateway.attacks` actually registers. It previously held the *subtype*
(`hypothetical_framing`, …), which scigateway does not recognise, so
`categorize_session()` fell through to its `risk_indicators` fallback. That fallback
only fires when an injection **succeeded**, so the 85 resisted attacks were categorised
benign and the metrics read **315/285 instead of 400/200**, with an ASR that was 100%
by construction. Per-technique detail is preserved in `agent_config["subtype"]` and
`prompt_family`.

Note this is *direct* injection — the payload arrives in the user's own prompt.
Indirect / website-embedded injection is Evangeline's track.

## Notes

- `fabricated_context` is the same technique the general model calls **`false_precedent`** (alias).
- `prompt_leaking` labels are provisional — its `leak_markers` (real system-prompt
  fragments) still need to be pulled from a live session before it scores beyond
  "ignored". Its 0.00 success rate is an **unmeasurable, not a result**; exclude it
  from per-technique comparisons.
- Raw native logs (~1.2 GB of `session_*.jsonl` + `gateway_*.log`) are **not** committed
  (too large; already parsed into `sessions.jsonl`). Regenerate with `prompt-injection/collect.py`.
- Not yet included: **Multilingual/Translation** (a wrapper, planned as a follow-up)
  and **Emotional Coercion** (built but assigned to a teammate).
